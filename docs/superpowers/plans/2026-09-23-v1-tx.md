# V1 Classic-ESP32 TX Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run custom BME680 and MQ-135 sensing, persistent HTTP delivery, and CSI probe traffic on the V1 classic-ESP32 TX board.

**Architecture:** Port the repository-owned register-level BME680 component into V1, then build a dedicated `node1_sensor_tx` app. A low-rate JSON record is retained in NVS until an exact HTTP ACK; separate UDP packets provide CSI traffic.

**Tech Stack:** ESP-IDF 6.1, C, host C tests, ESP32-D0WD-V3, NVS, HTTP client, UDP.

**Spec:** `docs/superpowers/specs/2026-09-23-v1-tx-and-evidence-dashboard-design.md`

## Global Constraints

- Stay on branch `v1`; do not overwrite modified `environmental_node` files.
- BME680 production driver is custom; the external diagnostic library is not a production dependency.
- SDA GPIO21, SCL GPIO22, address `0x76`; MQ-135 AO through 10 kΩ/10 kΩ divider to GPIO34.
- No ppm, IAQ, or calibrated gas-risk claim. `UNAVAILABLE` remains explicit.
- No RX firmware changes in this plan.

## Review Focus

- BME680 absent or wrong chip ID: TX reports a sensor error, not fabricated values; Task 1 host test and Task 3 live check.
- First zero gas-resistance sample: JSON uses `null`/invalid, not a safe gas classification; Task 2 serialization test.
- HTTP 200 with wrong event ID: NVS record remains queued; Task 2 ACK test.
- Wi-Fi/endpoint outage across reboot: same event ID is restored and retried; Task 2 queue test and Task 3 hardware check.
- MQ-135 ADC zero: report raw zero and uncalibrated status; Task 2 payload test.

### Task 2: TX record and reliable transport

**Files:** Create focused files under `firmware/node1_sensor_tx/main/` for `main.c`, telemetry serialization, HTTP ACK handling, and Wi-Fi/UDP; reuse `firmware/components/delivery/delivery_queue.c` and `firmware/components/gas_risk/gas_adc_esp_idf.c`; add matching portable tests in `firmware/tests/`.

**Interfaces:** JSON request includes `schema_version`, `event_id`, `tx_device_id`, `sequence`, sensor values/validity; exact response `{"event_id":"...","status":"ACCEPTED"}` removes only the queue head.

- [ ] Write tests for zero/invalid gas, raw MQ-135 zero, bounded JSON, and exact ACK parsing; run them and confirm behavior is missing.
- [ ] Implement serialization and ACK parser with no fabricated risk or RX status; run the focused tests green.
